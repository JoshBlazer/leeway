## What the tests cover

- **Merge laws** for counters, registers, sets, and whole documents, on states built from arbitrary operation lists, so they are reachable ones.
- **Escrow:** after every operation in arbitrary sequences, the total is conserved, consumption never exceeds it, and nothing goes negative. An honest wallet's reports never produce an overdraft, in any order.
- **Clocks:** stamps always increase, a write that saw a stamp beats it, and a device's stamps stay in sequence order for any arrival order and times.

## Do the tests catch anything?

They all passed the first time, which proves little, so I broke the code on purpose. Making the counter merge add totals instead of taking the maximum failed 5 of the 32 tests at that point, and the change was reverted.

## What these tests missed

The simulator in M2 found three bugs after this suite was green. See `m2.md`. One property test, for any arrival order, was added because of that. **Passing merge laws say the pieces are right. They do not say the protocol is.**
