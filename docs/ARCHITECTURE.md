# Architecture (draft)

Draft after M0. The data flow below assumes **ADR-0012, which is proposed and not yet accepted.**

```
 ┌──────── Avalonia / MAUI app ────────┐          ┌────────── ASP.NET Core server ──────────┐
 │ Offline DbContext (Datasync)        │  sync    │ Datasync table controllers              │
 │ Leeway.Datasync.Client              │◀────────▶│ Leeway.Datasync.Server                  │
 │  - op log (UUIDs), HLC              │          │  - escrow authority (grants, returns)   │
 │  - field-semantic conflict resolver │          │  - idempotent op application            │
 │  - lease wallet, provisional ops    │          │  - invariant checks, conflict outcomes  │
 └─────────────────────────────────────┘          └─────────────────────────────────────────┘
          ▲ generated by Leeway.Generators      Leeway.Core (pure, no Datasync dependency)
```

## Proposed data flow (ADR-0012)

**Local write.** One SQLite transaction, with no network:
record the op in a local log, update the wallet if escrowed, and advance the HLC. The UI shows `pulled row + unacknowledged ops`.

**Sync.**
1. Push ops as inserts into an append-only table with client-generated IDs.
2. Treat a 409 as already applied (C14).
3. Check the queue, because `PushResult` can report false success (C24).
4. Pull projections. Entity rows are never pushed, so they cannot conflict (C06).

**Server.** One transaction in a custom repository: dedupe by op ID, merge into per-field state, enforce invariants, record the outcome, and stamp `UpdatedAt` strictly increasing (ADR-0013).

## Why not a client resolver alone

See `docs/design/datasync-integration.md`: the merged write is unconditional (C09, C10), rows have lost the intent (C07), and retries are normal (C12, C13, C24, C25).

## Testing the design

| Layer | Tool | Location |
|---|---|---|
| Pure logic | xUnit, FsCheck | `tests/Leeway.Core.Tests`, `tests/Leeway.Property.Tests` |
| Whole protocol under faults | Simulator with mutation corpus | `tests/Leeway.Simulation.Tests`, `mutants/` |
| Datasync behaviour | Probes over real HTTP and SQLite | `tests/Leeway.Integration.Tests` |
| Generator and analyzer | Verify, Roslyn test harness | `tests/Leeway.Generators.Tests`, `tests/Leeway.Analyzers.Tests` |
| Full app | Headless window with real input, plus a live demo script | `tests/GateKeeper.Desktop.Tests`, `scripts/m0-demo.ps1` |

The simulator runs on `Leeway.Core` and a modelled transport, not real Datasync clients, because Datasync's sync lock is process-wide. Its fault model must include the real transport behaviours M0 found: C12, C13, C19, C24, C25.
